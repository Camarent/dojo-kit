# web

The home screen shows segmented progress bars (new/learning/learned) for each unit and for the whole course (`ProgressBar`, `web/ui/app.js:239`; used in `Home` at `web/ui/app.js`; the bars). A record is learned when `stage >= threshold`. The threshold is `course.learnedStage` (integer >= 1), else `DEFAULT_LEARNED_STAGE` = 4 (`web/session.js:29`), clamped to the last index of the unit's ladder (`getUnitThreshold`, `web/session.js:187`).

## Settings precedence (current behaviour)
- Per-unit override is stored per field: `doc.settings["unit:<unitId>:<field>"]` (key built by `unitFieldKey`, `web/session.js:214`; written by `setUnitSetting`, `web/session.js:255`). Fields: `newPerDay` (0..50), `ladderScale` (0.25..4), `dropOnWrong` (0..10), `newOrder` (`file` | `random`). Reads go through `getUnitSettingsOverride` (`web/session.js:232`), which drops invalid values (`validateUnitOverrideField`, `web/session.js:223`). A `null` value is a tombstone: it is stored as `null` with a fresh `doc.settings.ts` entry and reads as absent.
- Course-level resolution is one WASM call, `unitConfig(unitId)` (`web/session.js:219`; `unitConfig` in `crates/dojo-core/src/api.rs:412`, `unit_config` in `crates/dojo-core/src/srs.rs:96`). It returns `{newPerDay, ladder, dropOnWrong, newOrder, dropByType}` with no user overrides; `newPerDay` is null when the course sets no cap. The JS side layers the per-field override on top and does not re-implement the course rules.
- `examOnly` units: `preferShared` (`web/session.js`) drops items of `examOnly` units from the training, daily, practice and placement queues unless that would leave the queue empty; exams take `examOnly` candidates first (the `examOnly` flag is passed per candidate to WASM `sample`).
- Topic-level SRS: when a unit resolves `scope:"entity"` (WASM `unitConfig`), `web/session.js` builds `scopedMembers` (entity -> active ids) and passes it to `buildQueue`, `groupCounts`, `entityStates`; `nextRecord` returns a `{id: record}` map (WASM `applyEntity`), `commit` writes it in one `store.update`; `entityWrong` makes a repeated wrong in a session use relearn; `requeued` is keyed by entity; `lastAnswer.prev` is a per-member snapshot restored by `overrideLast`; `counts()` counts due scoped entities once; `weakQueue` keeps one id per scoped entity. Test: `web/tests/entity-scope.test.js`.
- `dropOnWrong` (`dropForItem`, `web/session.js:206`): override > WASM `dropForUnit` (unit `srs.dropOnWrong` > course `srsByType[type].dropOnWrong` > course `srs.dropOnWrong` > `COURSE_DEFAULT_DROP` = 1, `crates/dojo-core/src/srs.rs:20`). `LEGACY_VECTOR_DROP` = 2 (`crates/dojo-core/src/srs.rs:17`) applies only when `applyAnswer`/`applyPractice` get no `drop`.
- Ladder (`itemLadderFor`, `web/session.js:196`; `ladderForUnit`, `web/session.js:171`): core ladder (unit `srs.ladder` > `srsByType[type]` > course `srs` > `DEFAULT_LADDER`; the unit-level value from `unitConfig` is used by `ladderForUnit`), then `ladderScale` override scales it (`scaleLadder`, `web/session.js:246`).
- New-item cap per unit (`buildUnitNewCaps`, `web/session.js:490`): override `newPerDay` > `unitConfig.newPerDay` > uncapped. The global daily allowance is `engine.globalNewPerDay()` (`web/session.js:473`): `doc.settings.newPerDay`, else `DEFAULT_NEW_PER_DAY` = 10 (`web/session.js:26`).
- Groups (`course.groups`; `groupSettings` `web/session.js:378`, `setGroupSetting` `:388`, `groupCap` `:417`, `groupQueueArgs` `:457`, `groupCounts` `:725`): per-group override keys `doc.settings["group:<id>:<field>"]` with `doc.settings.ts` and `null` tombstone like unit settings; fields `newPerDay` (0..50), `newOrder` (`file`|`random`), `onlyTags` (boolean), `extraRandom` (boolean). `extraRandom` applies to the `extraNew` group's extra entities only (the +5/+10/+20 share): the base daily share keeps its order, entities beyond it are drawn in a seeded entity shuffle (`courseId|day|groupId|extra`), via the same two-pass `buildQueue` as `onlyTags`. Home toggle "Random order" is bound to `extraRandom`; `newOrder` stays a Settings-screen field. Precedence for the entity cap: override `newPerDay` > `group.newPerDay` > uncapped (the group then behaves like ungrouped units). Units of a capped group ignore unit caps and the global allowance in WASM and skip the JS item shuffle (WASM shuffles entities, seed `courseId|day|groupId`); the global allowance for ungrouped units is `newPerDay - (newByDay - sum of newBy:<unit> of capped-group units)`, and `extraNewByDay` goes to the `extraNew` group instead of the global allowance when that group is capped. `commit` writes `stats["newBy:g:<groupId>"][day] += 1` once per entity (when no other item of the entity has a record yet); `newByDay` and `newBy:<unit>` still count items. `extraNew` + `onlyTags`: the base share is unfiltered, extra entities beyond it must have an item tagged with one of `extraTags` (two `buildQueue` calls, fresh = base fresh + extra). `counts()` adds `groups`, `bars` (`{title, learned, started, total}`) and, with groups, `summary` `{due, newToday, queue}` (Home stat cards: due = sum of group due entities + due items of ungrouped units; newToday = sum of group `newToday` + fresh ungrouped items in today's queue) (from `groupCounts`; `newToday` there uses the course cap with the user override but ignores `onlyTags`) only when the course has `groups` or `bars`. Home group card `GroupCard`: labelled stats `group-<id>-due` / `-new` (due, new today), muted `group-<id>-notstarted` ("not started n of total"), start button "Start · N" (the session size hint lives once on Home as `session-count`, from `counts().summary.queue`), start button `btn-start-group-<id>` (`web/ui/app.js:697`), extra-new buttons and the "Random order" / "only tagged" toggles (`web/ui/app.js`); the `onlyTags` label shows `course.tagLabels[tag]` or the tag uppercased. Home progress rows use `ProgressMeter` (caption "Learned / In progress / Left / total" + 8px `ProgressBar` with `meter` aria-valuenow; colours from `--accent` and `--meter-started`, never `--warn`/`--good`); `Other sections` lists ungrouped units with `ProgressMeter` and a `unit-<id>-due` chip, units with `newPerDay: 0` sit in a collapsed `exam-units` details; the exam countdown is quiet muted text (`exam-countdown`, class `soon` at <= 7 days) with a locale-formatted date. Tests: `web/tests/home-ui.test.js`. Home sections in render order: `groups` list (`web/ui/app.js`), the `exams` section (`web/ui/app.js`, after groups), `bars` list (`web/ui/app.js`), then `other-units` and `exam-units` (`web/ui/app.js:891`). Settings: `group-settings` section (`web/ui/app.js`, one `btn-group-settings-<id>` per group) and dialog `group-settings-dialog` (`web/ui/app.js`); effective values by `getEffectiveGroupSettings` (`web/ui/app.js:2106`). Tests: `web/tests/groups.test.js`, Home cards `web/tests/groups-ui.test.js`, build-side `web/tests/groups-build.test.js`, Home `web/tests/home-app.test.js`.
- New-item order (`resolveNewOrder`, `web/session.js:515`): override `newOrder` > `unitConfig.newOrder` (unit > course > `file`).
- Engine helpers: `unitSettings(unitId)` (`web/session.js:242`) returns the validated override; `unitLadder` is `ladderForUnit`; `unitConfig` and `globalNewPerDay` are exposed on the engine (return at `web/session.js:1954`); `setUnitSetting(unitId, patch)` (`web/session.js:255`) returns `{error:'unknown_unit'}` or `{error:'bad_value'}` on failure. Patch values of `null` clear the field.
- Plugin settings (`DojoExt`, `web/ext.js`): see `ext.js` below. They are stored at `doc.settings["plugin:<key>"]` (`setSetting('plugin:' + key)`, `web/ui/app.js:1914`; `setSetting` at `web/ui/app.js`), not under `unit:`. The `plugin:` prefix is the only separation; the reserved-key list was removed.

## Purpose
Single-page app that runs a course in the browser. Grading, scheduling, merge and sampling are not done here; they are delegated to WASM through `DojoWasm`. The app renders, navigates, stores progress and looks up translations.

## Invariants and gotchas
- Course text goes through `DojoExt.text`: escaped plain text unless `course.markup` names a registered markup (`DojoExt.use` called at `web/ui/app.js`), in which case the markup's `render` vnode is used. Unknown markup names warn and fall back to plain text.
- Plugin settings are read-only config for hooks: they never change grading, scheduling or progress; `getSetting` never returns an unregistered option value.
- `DojoExt.detail` is called by the Catalog detail view only. The hook gets deep clones of the item, `ctx.items` and `ctx.records`; a throwing hook is logged and renders nothing. `ctx.introRendered` (boolean) is true when the detail's intro already produced `DojoExt.intro` output (`web/ui/app.js`), so the hook can avoid repeating it. Without a registered hook the detail view has no `detail-hook` element.
- Course plugins are build-time only: `dojo build` inlines `course.json` `plugins` files; nothing is loaded at runtime. Hooks never grade, schedule or write progress.
- `DojoExt.beforeSubmit` can only block a submit with `{message}`; it can never change the graded input. A throwing hook is logged and treated as `null`.
- No network at runtime in the artifact sandbox: Preact and htm are vendored and inlined by the build.
- Storage errors must not break the app: `safeLocalStorage` in `web/boot.js` returns `null` when storage is unavailable.
- WASM `call` results can be the refusal values `{"error":"course_mismatch"}` or `{"error":"invalid_document"}` (see `crates/dojo-core/src/api.rs`); callers must check them.
- A new question type needs a `web/types/<name>.js`, a `<name>` entry in `web/bundle.json` scripts, and a matching Rust item type.
- Stimuli come only from `content.json` `stimuli` (absent when the course has none); the session never fetches them. An unknown stimulus id yields `stimulus: null` rather than an error.
- Stimulus styles are `.stimulus`, `.stimulus-title`, `.stimulus-text` in `web/styles/app.css`; play button is `.btn.play` (`web/styles/app.css:39`).
- `text(str, {annotate:true})` returns `str` unchanged when no markup is active (`web/ext.js:461`); annotation needs an active markup and a loaded reading dictionary.
- `text(str, {annotate:true, hide:[...]})` renders segments whose reading is in `hide` (exact match) as bare base (`web/ext.js:294`); the session prompt passes the item's accepted answers via `answerReadings` (`web/ui/app.js:21`) so answers are not shown as furigana.
- Speech text comes only from `speak`: stimulus `speak.lines` or item `speak` string. `DojoSpeech.lines` passes it through `DojoExt.plain`, so markup is never spoken.
- Speech never grades, schedules or writes progress. It uses the browser's `speechSynthesis`. When a remote voice (e.g., Chrome "Google ..." or Edge "Online") is used, the browser may send the utterance text to a vendor server. `pickVoice` prefers voices with `localService === true` to avoid this.
- Exam: a stimulus play button can be used once per session. `played` lives on the SessionScreen (`web/ui/app.js`) and is keyed `s:<stimulus id>`, so items that share a stimulus share the flag. Play buttons in exam are disabled once played (`web/ui/app.js`).
- Exam timer groups: when a group's deadline passes, `expire()` jumps to the next group's first item (speech stopped, `web/ui/app.js`); the last group's expiry finishes the exam. Finishing a group early starts the next group clock on entry. Without `timing` a single global timer is used.
- Exam training (`training: true`): untimed, per-answer feedback shown, nothing written to `doc.exams`; results say so. Training is offered only for timed exams on the home picker.
- Exam wake lock: requested only for a timed, non-training exam and released on finish or leave. It is best effort: missing, rejected or throwing `navigator.wakeLock` never breaks the session.
- Exam scoring: when the exam has `scoring`, WASM `score` gets `scoring`, the section ranges and `passPoints`; stored entries get `examId` (legacy `default` exam omits it) and `parts`/`totalPoints` when present.
- Practice: play buttons replay freely. Leaving a question (`SessionScreen` next, `web/ui/app.js`) or the session calls `DojoSpeech.stop`.
- Placement (`mode 'placement'`, either placement mode): each answer writes just the item record (`commit`, `web/session.js:1449`; the `mode === 'placement'` return at `:1456` skips `doc.stats`), and `store.noteAnswer` is skipped (`:1480`), so placement does not change streak or daily counts. In self mode answers other than `known`/`again` are rejected with `bad_input`.
- Placement self mode never grades: `result()` returns `{recorded:true}` (`web/session.js:1495`), so no expected answer or explanation is shown. Placement check mode (the default) returns `correct`, `expected` and `explanation` like a normal item (`web/session.js:1487`-`1493`). Stage and due values come only from WASM `applyPlacement`; JS does no SRS math.
- "I don't know" (`session.dontKnow`, `web/session.js:1554`) is scored as a wrong answer: `nextRecord(item, false, ...)` writes the record, and `recordGrade` (`web/session.js:1579`) requeues the item outside exams, as for a wrong answer. It is refused with `no_dont_know` unless `course.dontKnow === true`, and always in placement, for `card` items and in real exams (training allowed). Label: `session.dontKnow` in `web/i18n/en.json` and `web/i18n/ru.json`.
- Placement `session.seed` defaults to `String(now())`; passing `opts.seed` makes the sample and per-item seeds reproducible. Each item uses `hashString(session.seed + '|' + item.id)`.
- `doc.settings.placementDone` is written only by `finish()` (`web/session.js:1816`); until then `engine.placement().done` is false. Re-running after completion is allowed from Settings.
- The App clears `placementIntro` on every `go()` (`web/ui/app.js:2507`), so the Back button and nav leave the placement intro.
- `hideText: true` with `speak`: the text stays hidden while speech is `ok`; when voice is missing or speech is unavailable the text is shown with a `speech.novoice` notice. `hideText: true` with no `DojoSpeech` loaded hides the text with no notice.
- Speech i18n keys: `speech.*` in `web/i18n/en.json` and `web/i18n/ru.json`.
- i18n lookup (`makeT`, `web/ui/app.js:140`): for each key the languages are tried in order `lang` -> primary tag -> `en`; inside a language a plural key is tried first as `key.<form>`, then the plain key. A missing key returns the key itself. Placeholders `{name}` are replaced only when supplied.
- Plural rule (`pluralForm`, `web/ui/app.js:129`): `ru` uses `one` / `few` / `many`; every other language uses `one` / `other`. The lookup adds `other` and `many` as fallbacks. Limitation: `.zero` and `.two` are never selected at runtime.
- Course language build: when no UI file (shipped in `web/i18n/` or the course's `i18n/`) matches the course language, the build warns and falls back to `en` (`crates/dojo-cli/src/main.rs:372`). Partial dictionaries are covered by `web/tests/i18n-partial.test.js`.
- Gap retry: a gap input that matches a `retry` reading (and no answer) returns `{verdict:'retry', retry:true, expected, explanation}` from `session.answer` (`web/session.js:1544`). Nothing is recorded, counted or advanced, and the UI keeps the question open (`web/ui/app.js`). In a real exam (not training) the same input is graded wrong with no hint (`web/session.js:1541`). Items without `retry` readings never call `gapVerdict` (`gradeInput`, `web/session.js:1292`).
- Override: `canOverride()` (`web/session.js:1622`) is true only right after a wrong gap, cloze or numeric answer in daily, practice or weak mode, when `course.allowOverride !== false` (`:1625`). Never in exams (training included) or placement, and never after "I don't know". `overrideLast()` restores the pre-answer record, applies the answer as correct, fixes the review row and drops the requeued copy. It does not call `commit`, so stats and `noteAnswer` are not updated a second time. The stored record equals a correct answer's; counters stay monotone for merge safety, so a copy already synced before the override can still carry `bad:1`.
- Counter: progress shows `min(position, initialTotal) / initialTotal`; requeued copies do not grow the displayed total and are shown only in the `retry-badge`.
- introNew: `shouldShowIntro` is true at most once per item, only for items with no record yet, only when `course.introNew` is set and the item has an `explanation`. Placement and real exams never show it. The intro is shown on the first try, not on the requeued copy.
- More new: `doc.stats.extraNewByDay[YYYY-MM-DD]` adds to the daily new allowance (`newAllowance`, `web/session.js:478`: `newPerDay + extra - newByDay used`) and never changes `newByDay`. New-item order: `resolveNewOrder` (`web/session.js:515`) gives override `newOrder` > `unitConfig.newOrder` (unit > course > `file`); `random` shuffles each unit's own slots in `builtQueue` (`web/session.js:536`) with a seed `courseId + '|' + today() + '|' + unitId` (`web/session.js:569`), so units do not affect each other's order. Core merges it per day by max because its keys are date keys (`crates/dojo-core/src/progress.rs`, `merge`).
- Unit ladder and drop: the engine calls WASM `ladderForUnit` and `dropForUnit` (`ladderForUnit`, `web/session.js:171`; `dropForItem`, `web/session.js:206`) with `unitId` and `itemType`, so the resolution order lives in core (`ladder_for_unit_json` and `drop_for_unit_json`, `crates/dojo-core/src/srs.rs`). - Unit new caps: `unit.newPerDay` (a number >= 0) or the override `newPerDay` caps new items per unit per day. Today's used count is `doc.stats["newBy:<unit id>"][YYYY-MM-DD]`, incremented in `commit` (`web/session.js:1449`; unit counter at `web/session.js:1473`-`1476`) only for counted new answers with `item.unit`; placement never writes it. Caps reach WASM `buildQueue` as `unitNewCaps` and `itemUnits` (`buildUnitNewCaps` `web/session.js:490`, `buildItemUnits` `:505`). Hostile non-object `newBy:*`, `newByDay` and `extraNewByDay` values are replaced with `{}` on write (`ensureObject`, `web/session.js:76`).
- Storage trim: when the document is over the size limit, `buildBody` (`web/storage.js:215`) empties the `newBy:*` counters together with `days` and `newByDay`. If still over and the slot is open, its answers keep only `{i, c}` (no `g`); if still over, the open slot is not sent: the remote body gets a payload-free `expired` tombstone of the newest closed sid that carries `closedSids` (`web/storage.js:230`-`233`), or no `examDraft` when there are no `closedSids` (`web/storage.js:235`). A closed slot is kept unchanged; a body still over the limit gives up (`null`, `web/storage.js:239`). The local document is never trimmed this way. Reset (`emptied`, `web/storage.js:434`) deletes `examDraft` (`web/storage.js:442`).
- Exam draft: only timed, non-training exams write `doc.examDraft` (`saveDraft`, `web/session.js:1158`). Each answer is written at once; other writes are throttled to 1 s, and `tickDraft` (`web/session.js:1183`) forces a write every 60 s. `SessionScreen` calls `saveDraft` on `pagehide` and on hidden `visibilitychange` (`web/ui/app.js`).
- Draft slot: an open draft is `{sid, examId, ids, sections, index, group, remainingMs[], elapsedMs, answers[{i, c, g?}], startedAt, updatedAt}`. A closed slot is `{sid, updatedAt, closed: 'finished' | 'abandoned' | 'expired', closedSids[]}` (`closeSlot`, `web/session.js:1914`); `closedSids` entries are `{sid, updatedAt}`, sorted by `updatedAt`, and keep the newest 32 (`MAX_CLOSED_SIDS`, `web/session.js:35`). Closing a sid while another sid's slot is open keeps that slot open, adds the sid to its `closedSids` and sets its `updatedAt` to `max(prev, t+1)`, so the open slot wins a merge against a tombstone written at the same time.
- A closed sid is never written again: `saveDraft` checks `closedSids` (`web/session.js:1169`). `finish()` returns `finished_elsewhere` for a sid that is `finished` in the slot or listed in `closedSids` (so abandoned and expired sids too); the check runs inside the same `store.update` that writes `doc.exams` and the `finished` tombstone (`storeExam`, `web/session.js:1767`; check at `:1781`-`1788`, return at `:1794`).
- `examDraft()` (`web/session.js:1931`) tombstones the slot as `expired` when it fails `validateDraft` (`web/session.js:1875`) or is older than 7 days (`DRAFT_EXPIRY_MS`, `web/session.js:32`). `validateDraft` clamps each `remainingMs[k]` to the group's minutes (the exam's minutes when untimed; `web/session.js:1895`-`1896`) instead of rejecting it. Answer `given` text is cut to 200 chars (`MAX_ANSWER_G`).
- Resume replays saved answers into `review` and `graded` only; it does not call `commit`, so SRS and daily stats are not counted again. `startedAt` is shifted back by `elapsedMs`, so time away does not count.
- `homeData` (`web/ui/app.js:2483`) calls `engine.examDraft()`, so opening Home can write an `expired` tombstone. `exitSession` (`web/ui/app.js:2520`) calls `session.abandon()`, so leaving a timed exam discards its draft (`abandoned`).

The set is the Han characters of `course.ruby.skip` plus those of the string at item path `skipKey` (default `meta.kanji`) of every item tagged `skipTag`. `rubyRender` (`web/ext.js:278`) shows a `{base|reading}` as bare base when every Han character of base is in the set; a base with any other kanji keeps its reading. Only the built-in `ruby` markup uses the set. `rubyPlain` (`web/ext.js:305`) always drops the reading, so speech, Catalog search and plain text are unaffected.
- `course.ruby` and `course.captions` are typed in core only (`crates/dojo-core/src/content.rs`); `validate.rs` has no check for them, so a bad value shows up only in the browser.
- Session keys, `SessionScreen.onKey` (`web/ui/app.js`): ignored when a confirm dialog is open, there is no current item, or `DojoTypes.keyBlocked(e, {allowInput: true})` is true (modifier keys or a contentEditable target). Without a shown result (e.g. an exam question before its answer) ArrowRight does nothing. When a result is shown and focus is on the Next button (`btn-next`, `this.nextBtn`), ArrowRight advances too (`web/ui/app.js`); other buttons still ignore ArrowRight.
- Choice keys, `onKey` (`web/types/choice.js:43`): nothing while a result is shown; ignored with modifiers or on INPUT, TEXTAREA, SELECT, contentEditable targets (`DojoTypes.keyBlocked`, `web/types/registry.js:38`). ArrowUp/ArrowDown move focus between `option-<index>` buttons (`web/types/choice.js:47`-`53`), off in exams. Enter and Space pick the focused option (not in exams); digits 1-9 pick by position.
- `DojoTypes.keyBlocked(e, opts)` (`web/types/registry.js:38`) is the shared key guard: true for modifier keys and contentEditable targets, and for INPUT, TEXTAREA and SELECT targets unless `opts.allowInput` is set. `SessionScreen.onKey` (`web/ui/app.js`), `CatalogScreen.onKey` (`web/ui/app.js`) and `choice.js` `onKey` use it.
