# crates

Three crates: `crates/dojo-core`, `crates/dojo-cli`, `crates/dojo-wasm`. Sections below follow that order.

## crates/dojo-core

`learnedStage` (course.json, integer >= 1) is typed here and validated (`bad_learned_stage`); core reads it in the groups logic: `group_counts` (`crates/dojo-core/src/groups/counts.rs`) applies `DEFAULT_LEARNED_STAGE` = 4 when unset; `entity_stats` takes the stage as a parameter. The browser clamps the unit threshold to the unit ladder's last index in `web/session/overrides.js` (`getUnitThreshold`).

### Purpose
Library crate holding every decision that must be correct: what an answer grades to, when an item is due, how two progress documents merge, how an exam is sampled and scored, and which course/content problems are reported. It has no clock and no I/O; callers pass `now` and `seed` in. Shared by `dojo-cli` (native) and `dojo-wasm` (browser).

### Invariants and gotchas
- No clock, no randomness, no I/O in this crate: `now`, `seed`, timezone offset are arguments.
- `api::call` returns the merge refusal as a successful value `{"error":"course_mismatch"}` or `{"error":"invalid_document"}` (`crates/dojo-core/src/api/`), not as an error envelope. JS callers must check for it.
- `gapVerdict` checks `answers` first: an input that matches an answer is `"ok"` even when it also matches a `retry` reading. `"retry"` only when no answer matches. `checkGap` ignores `retry`; the browser calls `gapVerdict` only for gap items that have `retry` readings.
- `retry` is typed on gap items only (`GapItem`, `crates/dojo-core/src/content/`); on another item type it is a parse error (`deny_unknown_fields`). A retry reading equal to an answer after normalization is `bad_retry` (error, `bad_retry` in `src/validate/`); an empty one is `gap_empty_answer`.
- `sanitize` of a non-object returns `null` through the API (`crates/dojo-core/src/api/`).
- `opts.fold` is checked in `normalize_opts` (`crates/dojo-core/src/api/`): a malformed entry makes the call return an error envelope; it is not ignored.
- Exam sampling (`crates/dojo-core/src/exam/`): candidates sharing a `stimulus` id are drawn as one group, whole and in input order; `count` counts items. A group larger than the remaining count is skipped (later groups may still fit). If a section is still short and some group has more than one item, a subset-sum pass (`reach` table in `sample`) picks the largest total <= `count`, and replaces the greedy picks only when it fills more. A `count` larger than the candidate pool is clamped to the pool size before the `reach` table is built (no allocation proportional to a huge `count`). The unfilled rest goes to `short` (`Shortage.short_by`); a section's `count` in `sections` is what was actually filled.
- Exam ids: `exams[]` entries need an id matching the course-id charset (`bad_id`), unique; the legacy `exam` must be id `default` or omitted, and it collides with an `exams[]` id `default` (`bad_exam`) (`check_course` in `src/validate/`).
- `timing` and `scoring` section titles must exist in the same exam's `sections` (`unknown_section`). Validator reports: `bad_exam` (0 minutes, empty group, 0 or negative points, `minPoints > points`, negative `passPoints`, a section in two timing groups or two scoring parts, empty `scoring[].sections`, timing group sections not consecutive in exam order).
- `compute_parts` (`crates/dojo-core/src/exam/`) errors, and the API returns an error envelope, when a part names an unknown section, a section is used by two parts, or a points value does not fit in u32 (`scoring[].points`/`minPoints` are range-checked in `crates/dojo-core/src/api/exam.rs` too). Part points are `round(points * raw / total)`; a part with total 0 scores 0.
- `score_with_parts` (`crates/dojo-core/src/exam/`): `pass` = fraction >= passMark (default 0.6 when absent) AND every part's `minPoints` met AND (when set) sum of part points >= `passPoints`. Without `scoring` the output is the plain `score` result (no `parts`).
- `stimulus_group_split` (warning, `check_stimulus_groups` at `crates/dojo-core/src/validate/`): items sharing a stimulus differ in unit, tags, or type, or include a card.
- Stimulus validation: `stimuli.jsonl` line errors are `parse_error`; duplicate ids are `duplicate_stimulus`; an item whose `stimulus` is unknown is `unknown_stimulus` (code table `crates/dojo-core/src/validate/`). Items whose stimulus has `hideText: true` skip the leak check (`check_leak`, `crates/dojo-core/src/validate/`).
- Course `inputScript` (script names) and `speech.voices[role].prefer` (regex sources) are validated by `unknown_input_script` and `bad_voice_pattern` (`regex_problem` in `src/validate/` is a structural check, no regex engine in core).
- Speech validation: `bad_speech` covers rate outside 0.1..10, pitch outside 0..2, empty voice label or `match`, empty `speak.lines`, empty line text, and an empty item `speak` string. `unknown_voice` covers a line `voice` not in `speech.voices`, and any named voice when `speech.voices` is absent (`crates/dojo-core/src/validate/`).
- A stimulus `speak` is typed (`Speak`, `deny_unknown_fields`): non-conforming JSON is a parse error, not passed through. Item `speak` stays an opaque string.
- Placement: `course.placement.perUnit` is validated (`bad_placement` if < 1, in `check_course`) and defaults to 5 (`PlacementConfig`, `crates/dojo-core/src/content/`); `web/session.js` reads it for placement queues.
- Unit `placement: false` (`crates/dojo-core/src/content/`) is documented as excluding the unit from placement (`crates/dojo-core/src/schema.rs`); core only stores and validates it, it does not filter queues on it. `placement_unused` (warning, `crates/dojo-core/src/validate/`) fires for such a unit when `course.placement` is absent. `bad_placement` also fires when `course.placement` is set and no unit with `placement !== false` has active items.
- `applyPlacement` (`crates/dojo-core/src/srs/`): `known = false` returns the record unchanged (null stays null). A record whose stage is already >= min(4, max stage) is returned unchanged. Otherwise stage becomes that target, `last = now`, `ok`/`bad` default to 0 when absent, and an unseen item becomes a new record. `due = now + round(ladder[target] * (0.6 + 0.8 * r))`, where `r` is the top 53 bits of one splitmix64 step over `seed` divided by 2^53 (in `apply_placement`). Rust and `tools/reference/srs.js` must agree (vectors in `tests/vectors/srs.json`).
- Fold runs after case folding and before strip-punctuation, collapse and trim (`crates/dojo-core/src/check/`). Entry forms: single char -> any string (`""` deletes), or equal-length range `"A-Z"` -> `"a-z"` mapped char by char. First matching entry wins.
- `normalize` itself silently skips malformed fold entries; only the validator (`bad_fold`) and `api` reject them. `fold_too_large` fires for more than 256 entries or a single-char entry whose target exceeds 16 chars (counted in chars, not bytes).
- Empty `fold` leaves the text unchanged, so answers without fold keep their verdicts.
- `bad_plugin_path` is only the syntactic check (absolute, `\`-rooted, drive letter, or a `..` segment). Missing, outside-folder, symlink-escape and non-file checks are in `dojo-cli` (`validate_course`).
- Each of the 8 item structs carries an optional free-form `meta` (`serde_json::Value`, e.g. the `Item` structs in `src/content/`) and an optional `stimulus` id; core never reads `meta`. `deny_unknown_fields` on `Plugins` means unknown plugin keys are rejected.
- Course `normalize` is used only by the validator's duplicate-prompt and leak checks (`fold_norm`, `src/validate/`): the item's normalize object if its fold is non-empty, else the course's if its fold is non-empty, else the item's own. The browser engine instead uses `item.normalize || course.normalize` as a whole object (`web/session.js` `normalizeOpts`); change both together.
- `apply_answer` on a wrong answer drops `LEGACY_VECTOR_DROP` (2) stages but never below 1 for an item that was ever learned; `due = now + ladder[stage]`. `apply_answer_drop` allows configuring the drop.
- `apply_practice` on a correct answer to a started, not-yet-due record only bumps `ok` and `last`. `apply_practice_drop` allows configuring the drop.
- `drop_for_unit_json` resolves `dropOnWrong` with order: unit > course srsByType[itemType] > course srs > 1; always returns a value, `COURSE_DEFAULT_DROP` (1) when nothing is configured; values outside 0..=10 fall through to the next level. `LEGACY_VECTOR_DROP` (2) applies only when `applyAnswer`/`applyPractice` get no `drop` (`drop` in `crates/dojo-core/src/api/mod.rs`).
- Topic-level SRS (`srs.scope:"entity"`, `SrsScope` in `src/content/`): `srs::entity_view`, `srs::apply_entity` (`EntityMode` Answer/Practice/Relearn/Placement; returns `{memberId: record}` for every active member), `srs::pick_drill`; `groups::build_queue_scoped` (representative pass over `build_queue_with_groups`, `Scope{members,drill}`), `groups::group_counts_scoped` / `entity_stats_scoped`. WASM names: `entityView`, `applyEntity` (members `[{id,status?,retired?}]`, retired filtered in api), `buildQueue` + optional `scopedMembers`/`scopedDrill` (output gains `drills` only when `scopedMembers` is present), `groupCounts`/`entityStates` + optional `scopedEntities`. `unitConfig` also returns `scope` and `drill`. Validator codes `scope_by_type`, `bad_drill`, `mixed_entity_scope`. Tests: `crates/dojo-core/tests/entity_scope.rs`, vectors `entityView`/`applyEntity` and scoped `buildQueue` cases.
- `unit_config` (`crates/dojo-core/src/srs/`) is the only course-level resolver for per-unit settings: `newPerDay` = unit `newPerDay` (>= 0) or null; `ladder` = `ladder_for_unit_json` with no item type; `dropOnWrong` = `drop_for_unit_json` with no item type; `newOrder` = unit > course > `file`; `dropByType` = one `drop_for_unit_json` per type in `srsByType`. Do not re-derive these rules elsewhere (JS, CLI).
- `weakest` ranks by `(bad+1)/(ok+bad+2)` plus 0.1 when stage < 3; default limit 10.
- Progress objects keep unknown fields (`preserve_order`, `float_roundtrip`); do not add typed fields that drop them.
- `examDraft` (top-level, one slot, no version field) is either an open draft (`sid`, `updatedAt`, payload) or a closed tombstone (`sid`, `updatedAt`, `closed`). Core checks only that `sid` is a string and `updatedAt` a number (`is_valid_draft`, `crates/dojo-core/src/progress/`); `closed` must be a string. Payload fields are opaque and kept byte-identical; `sanitize` does not touch them (test `draft_sanitize_keeps_draft_byte_identical` in `src/progress/`).
- `merge` of drafts is a join (commutative, associative, idempotent). Drafts with `updatedAt` below `max(resetAt)` of the two sides are dropped (checked only when that `resetAt` is non-zero). The slot is the greatest candidate under `draft_cmp`: `updatedAt`, then `sid` (UTF-16), then closed over open; among closed the reason (`expired` lowest), among open more `answers`, then stable JSON.
- `closedSids: [{sid, updatedAt}]` is an optional bookkeeping list inside the slot, sorted ascending, at most 32 entries (newest kept, `CLOSED_SIDS_MAX` `crates/dojo-core/src/progress/`), absent when empty. Each input list is first trimmed to 128 valid entries (largest `updatedAt`, ties: larger sid; `bound_closed_sids`, `crates/dojo-core/src/progress/`, `CLOSED_SIDS_BOUND`). A sid listed there is closed whatever the slot holds. The synthetic tombstones it produces use reason `expired`.
- If no candidate survives `resetAt` but a valid draft existed, the `examDraft` key is removed. With no valid draft on either side, the generic top-level merge applies. An invalid draft never beats a valid one.
- Item ids must match `^[a-z][a-z0-9]*-[0-9]+$` (`validate` rule, `crates/dojo-core/src/validate/` `is_valid_id`); course ids use `is_valid_course_id` (`^[a-z0-9][a-z0-9_-]{0,47}$`).
- Per-unit settings (`course.units[]`): `newPerDay` (`crates/dojo-core/src/content/`), `srs.ladder`, `placement` and `newOrder` (`crates/dojo-core/src/content/`; enum `NewOrder`; order for new items: file or random). All are optional and absent means no change: `build_queue` with no caps is the old behaviour, and `content.json` serialization skips absent fields.
- `buildQueue` caps (`crates/dojo-core/src/srs/`): a fresh id is taken only while its unit's count is below `unitNewCaps[unit]` (the unit must be listed in both `unitNewCaps` and `itemUnits`; otherwise uncapped), and the global `newAllowance` still binds. Records that are not new do not count. A cap of 0 blocks the unit. Caps are counted over the items the queue takes, in `order`.
- `ladderForUnit` / `ladder_for_unit_json` (`crates/dojo-core/src/srs/`) work on the raw course JSON, so the WASM does not parse the whole course. Order: unit `srs.ladder`, then `srsByType[itemType].ladder` (only when `itemType` is given), then course `srs.ladder`, else `DEFAULT_LADDER`. A ladder counts only if it is a non-empty array of integers (`json_ladder`, `crates/dojo-core/src/srs/`); an empty or non-integer `srsByType` ladder falls through to the next step. An unknown unit falls through the same way. Drop resolution (`drop_for_unit_json`, `crates/dojo-core/src/srs/`): unit `srs.dropOnWrong`, then `srsByType[itemType].dropOnWrong`, then course `srs.dropOnWrong`, else 1.
- `bad_unit_settings` (`crates/dojo-core/src/validate/`): negative `newPerDay`, or a unit `srs.ladder` that fails `ladder_problem` (`crates/dojo-core/src/validate/`; same rules as course `bad_ladder`: at least 2 entries, non-negative, first 0, non-decreasing). The `CODES` text for `bad_unit_settings` says "non-increasing"; the code enforces non-decreasing, and equal neighbours pass.
- Groups (`crates/dojo-core/src/groups/mod.rs` module header): caps count ENTITIES; a cap never splits an entity (all items of an admitted entity go into fresh); units of a capped group are exempt from unit caps and the global allowance. `group_counts` ignores retired items.
- Adding an item type means a new `Item` variant, a `check` function and a `web/types/<name>.js` file.
- New content-quality warnings (all severity: warning): `foreign_script` (text contains letters from a script not in Latin/Cyrillic/Hiragana/Katakana/CJK; whitelist via `course.scripts`), `prompt_type_mismatch` (prompt asks to write/type but type has no text input, or asks to choose/pick on a gap), `same_prompt_different_answers` (two non-stimulus gap/cloze/numeric items share the same normalized prompt but have different normalized answer sets), `ambiguous_answer` (`check_ambiguous_answer`, helper `has_slash_outside_brackets`; gap with several non-ASCII answers and no disambiguation hint like "any"/"one of"/digit/"любой"/"или", choice/multi option with '/' or '／' outside parentheses (ASCII `()` or full-width `（）`; a '/' inside parentheses is fine; nesting is handled; an unbalanced opener swallows the rest), or duplicate options after normalization; the warning advises to split into separate options or reword with "or"/"или"), `order_blanks_mismatch` (number of `___` blanks in prompt differs from number of steps in an order item).

### Depends on / used by
- Depends on: `schemars`, `serde`, `serde_json` (`crates/dojo-core/Cargo.toml`).
- Used by: `crates/dojo-cli` (validate, build, stats, add, lock, schema), `crates/dojo-wasm` (`api::call` only). Its own `tests/*_vectors.rs` read the shared `tests/vectors/` data.

## crates/dojo-cli

### Purpose
Command-line tool that turns a course directory (`course.json` + `content/*.jsonl` + optional `stimuli.jsonl` + `ids.lock`) into validated data and a published-ready `dist/<course>/` folder. It reads and writes files; all rules come from `dojo-core`.

### Public surface
Commands (`USAGE` and dispatch `run` in `crates/dojo-cli/src/main.rs`; each command is `run_<name>` in `crates/dojo-cli/src/cmd/<name>.rs`):
- `dojo schema --brief` and `dojo schema --out <dir>` (writes `course.schema.json`, `item.schema.json`).
- `dojo validate <course-dir> [--json] [--strict] [--web <dir>]` (`crates/dojo-cli/src/cmd/validate.rs`, `run_validate`). Exit 0 ok, 1 on errors (or warnings with `--strict`).
- `dojo lock <course-dir>` (`crates/dojo-cli/src/cmd/lock.rs`). Rewrites `ids.lock`.
- `dojo build <course-dir> [--out <dir>] [--wasm <file>] [--web <dir>] [--strict]` (`crates/dojo-cli/src/cmd/build.rs`). Default out `dist`.
- `dojo init <course-id> [--title T] [--ui LANG] [--content-lang LANG] [--workspace DIR]` (`crates/dojo-cli/src/cmd/init.rs`).
- `dojo stats <course-dir> [--json]` (`crates/dojo-cli/src/cmd/stats.rs`).
- `dojo next-id <course-dir> <prefix> [--count N]` (`crates/dojo-cli/src/cmd/next_id.rs`).
- `dojo add <course-dir> <unit-id> [--file F] [--dry-run]` (`crates/dojo-cli/src/cmd/add.rs`, logic in `crates/dojo-cli/src/cmd/add.rs`). Reads JSON objects from stdin or file; all-or-nothing. Exits 1 before reading the course when `<unit-id>` does not match the slug rule `^[a-z0-9][a-z0-9_-]{0,47}$` (`validate::is_valid_course_id`).
- `dojo import-progress <old.json> --map <id-map.json> --course <dir> [--out <file>] [--write] [--now <ISO>]` (`crates/dojo-cli/src/cmd/import_progress/`). Converts legacy progress to v:1 format; dry-run by default (prints report, writes nothing). `--write` requires an explicit `--out` (no default path) and refuses a symlinked target. Clamps by the course ladder only (unit-level ladders/scope are not consulted; course-level `srs.scope=entity` is). Only the target file itself is checked for symlinks; symlinked parent directories are not refused. Separate from load-time `supersedes` migration (`crates/dojo-core/src/migrate.rs`), which runs in the browser.
- i18n check: keys starting with `plugin.` or `course.` in a course `i18n/<lang>.json` are reserved for plugins/course and never warn `i18n_unknown_key` (`crates/dojo-cli/src/build/i18n.rs`; test `i18n_reserved_plugin_course_keys_do_not_warn`, `crates/dojo-cli/tests/validate.rs`).
- Exit codes (`main` in `crates/dojo-cli/src/main.rs`): 0 success, 1 validation or build refusal, 2 usage or I/O error.
- `--json` validate output: `{"ok","errors","warnings","diagnostics":[{severity,code,file,line,message}]}` (`print_json`, `crates/dojo-cli/src/cmd/validate.rs`).
- `validate`, `lock` and `build` all run `validate_course` (`crates/dojo-cli/src/course_files.rs`): `dojo-core` validate plus filesystem checks of `course.json` `plugins.{scripts,styles}`. Failures use code `bad_plugin_path` (file `course.json`, line 0).
- Build outputs under `<out>/<course-id>/`: `index.html`, `data/content.json`, `manifest.json`; `ids.lock` is rewritten in the course dir (`run_build`).
- `crates/dojo-cli/src/build/text.rs` `base64`, `fnv1a64`, `escape_script_text`, `escape_style_text`, `script_tag`, `license_comment`, `select_language` (in `crates/dojo-cli/src/build/i18n.rs`), `fill_template`.
- `crates/dojo-cli/src/cmd/add.rs` `run` (the `add` command).

### Key files
- `src/main.rs` - `USAGE`, `run` (command dispatch), `main`.
- `src/cmd/*.rs` - one file per command (`run_add`, `run_build`, `run_import_progress`, `run_init`, `run_lock`, `run_next_id`, `run_stats`, `run_validate`); `cmd/build.rs` holds `find_web_dir`.
- `src/course_files.rs` - `CourseFiles`, `load`, `check_symlink`, `i18n_check`, `validate_course`, `plugin_files`.
- `src/cmd/build_audio.rs` - audio pack limits used by `dojo build`: `MAX_FILE_BYTES` 16 MiB, `MAX_DIST_BYTES` 60 MiB, `MAX_FILES` 250; the build fails above them. Manifest copied to `data/audio/manifest.json`, packs to `data/audio/<file>`.
- `src/build/` - pure helpers for the build step: `text.rs` (encoding, escaping, template filling), `i18n.rs` (`select_language`, UI language files).
- `crates/dojo-cli/src/cmd/add.rs` - the `add` command (id assignment, unit check, append to JSONL).
- `tests/*.rs` - integration tests that spawn the `dojo` binary (`CARGO_BIN_EXE_dojo`) on fixtures and `examples/`.

### Invariants and gotchas
- `build` refuses (exit 1) on any validation error; with `--strict` also on warnings. It runs `validate` first.
- Build needs the WASM file (default `target/wasm32-unknown-unknown/release/dojo_wasm.wasm` next to `web/`; `run_build` in `crates/dojo-cli/src/cmd/build.rs`) and `web/bundle.json`; `web/` is found by walking up from the current directory unless `--web` is given (`find_web_dir`, `crates/dojo-cli/src/cmd/build.rs`).
- Plugins: each `plugins.scripts` entry is inlined as a `<script>` at the `@course` marker of `bundle.json` `scripts`; the build fails if the marker is missing while plugin scripts exist. Plugin styles are appended after all `bundle.json` styles (the `@course` entry in `styles` is skipped).
- Plugin CSS goes through `escape_style_text`; plugin JS through `script_tag` / `escape_script_text` (`</script` and, before a `<script`, `<!--` are escaped).
- `content.json` has `v`, `course`, `items`, `version` (16-hex FNV-1a of course + items JSON), and `lock`. When `stimuli.jsonl` has at least one stimulus, `content.json` also has `stimuli` and the hash input gets the stimuli JSON appended; without stimuli the output and version are unchanged. `course.speech` (when set in `course.json`) is in `content.json` `course` (`crates/dojo-cli/tests/build.rs`).
- `intros.jsonl` (course root, optional, symlinks refused) is loaded by `load`, checked through `validate_all`, and `build` writes its lines to `content.json` `intros` (only when non-empty; they are hashed into `version` only then, so courses without intros keep their version).
- `stimuli.jsonl` (course root, optional) is read by `load` (`crates/dojo-cli/src/course_files.rs`) and checked by `validate_course` (`crates/dojo-cli/src/course_files.rs`) through `validate_with_stimuli`; `build` writes its parsed entries to `content.json`.
- Size: warn above 8 MiB, fail above 16 MiB total (`WARN_BYTES` and `MAX_BYTES`, `crates/dojo-cli/src/cmd/build.rs`).
- UI language: the build embeds only `en` and the chosen `uiLanguage`. The chosen language is looked up among `web/bundle.json` `i18n` and the course's `i18n/<lang>.json` (`select_language` in `crates/dojo-cli/src/build/i18n.rs`); with no match the build warns and uses `en` (`crates/dojo-cli/src/cmd/build.rs`). Per language the web file is loaded first and the course file overlays it key by key (`crates/dojo-cli/src/cmd/build.rs`). A language listed in `bundle.json` without its web file fails the build.
- `validate`, `lock` and `build` check course UI files (`i18n_check`, `crates/dojo-cli/src/course_files.rs`): missing and unknown keys are warnings; non-string values and changed placeholders are errors.
- `add` assigns ids `<prefix>-<n>` above the highest existing number and never reuses ids present in content or `ids.lock`.

### Depends on / used by
- Depends on: `crates/dojo-core` (content, validate, lock, stats, schema, slug), `serde_json`.
- Used by: the repo-root `dojo` wrapper script (builds this crate and `crates/dojo-wasm`, then runs the binary); `prompts/` tell AI agents to call `./dojo`.

## crates/dojo-wasm

### Purpose
Thin WebAssembly wrapper over `dojo-core`. The browser calls one generic entry point with a function name and JSON arguments, and receives a JSON envelope. No logic lives here.

### Public surface
- `crates/dojo-wasm/src/lib.rs` `alloc(len) -> ptr` (exported `extern "C"`).
- `crates/dojo-wasm/src/lib.rs` `dealloc(ptr, len)` (unsafe; release each buffer once).
- `crates/dojo-wasm/src/lib.rs` `call(name_ptr, name_len, args_ptr, args_len) -> u64` - returns `(ptr << 32) | len` of a UTF-8 JSON envelope; the caller must `dealloc` it.
- Envelope and function names: see `crates/dojo-core/src/api/`.
- `migrateProgress` (via `call`, arm at `crates/dojo-core/src/api/progress.rs`): args `{doc, items:[{id, status?, supersedes?}]}`, value `{folded, skipped, doc?}` (`doc` only when something folded); refusal is an ok-value `{error: "bad_links"|"invalid_document", message}`. No change to the WASM ABI itself.
- Crate type `cdylib`, no wasm-bindgen (`Cargo.toml`).

### Key files
- `src/lib.rs` - all of the ABI; the functions are compiled only for `wasm32` (`#[cfg(target_arch = "wasm32")]`).
- `Cargo.toml` - depends only on `dojo-core`.

### Invariants and gotchas
- Input that is not valid UTF-8 returns a `bad_utf8` envelope instead of trapping.
- Built with `opt-level="z"`, `lto`, `panic="abort"` from the workspace `Cargo.toml`; a trap discards the instance on the JS side (see `web/dojo-wasm.js`).
- The build command is `scripts/build-wasm.sh` (wraps `cargo build --release -p dojo-wasm --target wasm32-unknown-unknown` with path remapping) (as in the repo-root `dojo` wrapper).
- Size budget 512 KiB is checked by `tests/wasm-smoke.js`.

### Depends on / used by
- Depends on: `crates/dojo-core`.
- Used by: `web/dojo-wasm.js` (loader), `dojo build` (embeds the `.wasm` as base64), `tests/wasm-smoke.js`.
