# dojo-kit contract

Current rules of the framework. Code, tests and `docs/modules/*` follow these; when one of them changes a rule, this file changes with it.

dojo-kit is a public MIT framework. A user drops materials into a course workspace, any AI coding assistant writes the content files, the CLI validates and builds them, and the result is published as a single-page app (a Claude artifact). The repo holds no personal data and no third-party copyrighted material.

Artifact sandbox: CSP blocks all network (`connect-src`). WASM (inlined as base64), Preact and htm (vendored, inlined), localStorage and the artifact database work; downloads are inert.

## 1. Scope
- Target: Claude artifact. No network use at runtime.
- Item types: `choice` (incl. true/false), `gap` (typed, normalized, several accepted, optional `retry` readings), `card` (self-rated, SRS), `multi`, `match`, `order`, `cloze`, `numeric`. Only `card` is self-rated; the others grade to a boolean.
- Modes: daily SRS, practice by tag/unit, weak points, placement test (when `course.placement` is set), timed mock exams (sections, pass rule, optional timing groups and scoring parts; only auto-scorable types).
- UI language is a course setting; `en` and `ru` ship; content language is independent.

## 2. Components
```
dojo-kit/
  crates/
    dojo-core/      pure Rust lib: content model (serde, deny_unknown_fields), srs, progress merge/sanitize,
                    answer check, exam sampler/scorer, semantic validator. No I/O.
    dojo-wasm/      cdylib: JSON-string-in/JSON-string-out wrapper over dojo-core for the browser.
    dojo-cli/       binary `dojo`: schema | validate | lock | build | init | stats | next-id | add.
  web/              Preact+htm UI (vendored), styles, i18n/<lang>.json, storage adapters (JS), app shell, plugin registry.
  schema/           generated JSON Schema (committed, regenerated by `dojo schema --out`).
  workspace/        user data (git-ignored except .gitkeep): one folder per course.
  examples/         small original demo courses (license-clean) and an example plugin
  tests/            golden vectors (JSON) shared by Rust tests and a JS smoke test
  tools/reference/  frozen reference JS (progress, srs) used only to generate the vectors
  prompts/          copy-paste prompts for AI assistants
  AGENTS.md  CLAUDE.md  .claude/skills/make-trainer/SKILL.md
```
The `./dojo` wrapper script at the repo root builds the CLI (and the WASM for `build`) when sources are newer, then runs it.

## 3. Layering
- Logic that decides what is correct or scheduled lives in dojo-core (srs, merge, check, exam scoring, validation). The browser calls it through dojo-wasm.
- JS owns rendering, navigation state, storage adapters (they touch `window.claude`/localStorage), i18n lookup and timers.
- WASM boundary: stateless pure functions, JSON in/out, `now` and `seed` passed in explicitly (no clocks or randomness inside core). Errors are returned as `{ok:false,error:{code,message}}`, never as panics across the boundary.
- WASM ABI: raw `cdylib`, no wasm-bindgen. Exports `alloc`, `dealloc`, `call(name_ptr, name_len, args_ptr, args_len) -> u64`; a hand-written JS loader (`web/dojo-wasm.js`). Base64 inlined in `index.html`. Size budget 512 KiB (gate: `tests/wasm-smoke.js`). After any trap the instance is discarded and re-instantiated, and progress is never saved after a failed call. If instantiation fails the app shows a read-only error screen.

## 4. Content model (authoring format)
- `course.json`: `{ id, title, uiLanguage, contentLanguage, types, modes, exam / exams[], units:[{id,title,placement?,newPerDay?,newOrder?,srs?,detail?,examOnly?}], srs?, srsByType?, newOrder?, learnedStage?, theme?, allowOverride?, introNew?, dontKnow?, placement?, speech?, markup?, ruby?, captions?, normalize?, inputScript?, groups?, bars?, tagLabels?, plugins?, detail?, breakdown?, scripts?, audio?, timer?, confusions? }`. `breakdown` is the opt-in Kanji/Han breakdown config (`crates/dojo-core/src/content/course.rs`, `Course.breakdown`); `scripts` is a course-level list of script paths, at most 20 entries, checked by the course validation in `crates/dojo-core/src/validate/course.rs`. Everything but identity and units is optional with defaults; `dojo schema --brief` prints the cheat-sheet and `schema/` holds the full JSON Schema.
  - `markup`: name of the text markup used by `DojoExt.text` / `DojoExt.plain`: a plugin-registered name, or the built-in `ruby` (`{base|reading}` renders as `<ruby>base<rt>reading</rt></ruby>`; `plain` keeps the base, so search and speech never see readings). `normalize`: `{fold: [[from, to], ...]}` character folding applied to typed answers (limits: `bad_fold`, `fold_too_large`). `introNew`: show the intro card once before the first question of a new entity.
  - `speech`: `{lang?, rate?, voices?: {<role>: {pitch?, rate?, match?, prefer?}}}`. `prefer` is a list of case-insensitive JavaScript regex sources matched against voice names, earlier = better; a matching voice ranks first within the language pool (after an exact `name` or `match` hit) and outranks the `registerVoiceRank` hook, which stays as an escape hatch. An invalid pattern is `bad_voice_pattern` (error; the check is structural: empty, unbalanced `(`/`[`, dangling `\`, nothing to repeat) and is skipped at runtime.
  - `ruby`: `{skip?, skipTag?, skipKey?}`; readings of the built-in `{base|reading}` markup are hidden when every kanji of `base` is in the skip set = Han characters of `skip` plus those of the string at item path `skipKey` (default `meta.kanji`) of items tagged `skipTag`. Display only.
  - `captions`: `{<tag or item type>: text}`; the small uppercase caption above a session question (first matching item tag, then the type, then the built-in `session.caption.<type>`).
  - `inputScript`: list of script names (`non-latin`, `han`, `hiragana`, `katakana`, `cyrillic`, `greek`, `arabic`, `hebrew`, `hangul`, `devanagari`, `thai`; unknown or empty = `unknown_input_script` error). On a `gap` or `cloze` item whose accepted answers contain a letter of a listed script, a typed answer containing Latin letters is blocked before submit with the i18n message `guard.script` (block-only like `beforeSubmit`: the graded input is never changed). Runs before the plugin `beforeSubmit` hook.
  - `units[].placement`: boolean; `false` excludes the unit from placement tests; absent means included.
  - `units[].newPerDay`: max new items per day for the unit.
  - `units[].examOnly`: boolean, default false; exam sections draw these items first and fill up from shared units (`sample` in `crates/dojo-core/src/exam/sample.rs`); training, daily, practice and placement prefer shared items and use examOnly ones only when the queue would otherwise be empty (`preferShared`, `web/session.js`). Validator warning `exam_few_unique` when a section has under 20% examOnly items. Pass rule and the 20% check: docs/AUTHORING.md "Exams".
  - `dontKnow`: enables the "I don't know" button in practice and training exam sessions (not in non-training exams, not for self-rated items).
  - `placement`: object with `perUnit` (number, default 5).
  - `groups[]`: `{id, title, units[], newPerDay?, newOrder? (file | random), extraNew?, extraTags?}`. Daily new caps count entities (see `entity` below), not items; a unit belongs to at most one group. `extraNew` marks the one group that takes `extraNewByDay` (the "more new" buttons); `extraTags` lists the tags used by the group setting `onlyTags`.
  - `bars[]`: `{title, units?, tags?, learnedStage?}`: progress bars on Home, counted over entities. `tagLabels`: `{tag: label | {label?, kind?: "public"|"internal"}}` for display; a tag without a label is shown uppercased; `internal` tags are hidden from the catalog chips (unknown `kind` warns `unknown_tag_kind`).
  - `detail`: `{fields: [{key, label?, labelKey?, type?, fields?}]}`: declarative detail rendering config from `item.meta`. `type` is `"text"`, `"list"`, or `"objects"`; `key` is a dot-separated path into `item.meta` (a leading `meta.` is optional); `labelKey` is an i18n key used when `label` is absent. Course-level `detail` applies to all units; per-unit `units[].detail` overrides for that unit. Missing/empty fields are skipped. Text is escaped; ruby markup and `renderText` are honored. A plugin `detail` or `intro` hook takes precedence. Unknown `type` is a validation error (`unknown_detail_type`).
- `intros.jsonl` (course root, optional): one card per entity, `{id, title?, text?, meta?, speak?}`; `id` is the entity id (`item.entity`, default the item id). With `introNew` the browser shows the card once, before the first question of a new entity; an item without an intro keeps showing its `explanation`. Validation: `duplicate_intro`, `bad_intro` (errors), `intro_unknown_entity` (warning). `dojo build` copies the lines to `content.intros`.
- `stimuli.jsonl` (course root, optional): shared passages, one per line `{id, text?, audio?}`; `audio?: [clipId]` (1..32 variants of the same utterance). `hideText` + `audio` in an item = listening stimulus. A `hideText` text is never shown before the answer, whatever the audio or speech status; without a playable source a notice is shown instead.
- Course UI translations (optional): a course folder may hold `i18n/<lang>.json` next to `course.json`. It has the keys of `web/i18n/en.json` with string values; `{placeholders}` must match the English ones (`i18n_placeholder`, error). `dojo build` loads the shipped `web/i18n/<lang>.json` first, then overlays the course file key by key, so a course can override single strings. A `uiLanguage` with no file in either place falls back to `en` with a warning and does not fail the build. Missing keys fall back to en at runtime; `validate`, `lock` and `build` report missing or unknown keys as warnings (`i18n_missing_key`, `i18n_unknown_key`) and non-string values as errors (`i18n_not_string`). Plural forms use the suffixes `.one`, `.few`, `.many`, `.other`: `ru` uses all four, other languages `.one` and `.other` only. Additive, no save-format change.
  - Topic-level SRS: `srs.scope:"entity"` (course `srs` or `units[].srs`; default `"item"`; not allowed in `srsByType`, code `scope_by_type`) schedules all ACTIVE items of an entity as one topic. The progress format is unchanged: a scoped entity is stored as identical `s,due,ok,bad,last` on every active member, so `merge` stays per item id and old clients lose nothing. Reconciliation happens only when reading (core `entityView`: `s`/`due` = min, `ok`/`bad`/`last` = max, other fields from the latest member) and when grading (core `applyEntity` writes the graded view to every active member, members without a record inherit). Intended lowering: the first grade after enabling scope (or after an old client advanced one member) writes min-view+1 to all members, lowering higher siblings; this happens only on a grade, never on load. A wrong answer drops the entity once per session (repeat wrongs use relearn). An entity is scoped only if all its active members' units resolve `scope:"entity"` (mixed: stays per item, warning `mixed_entity_scope`); its ladder and drop are the unit-level ones of its first active member (`srsByType` ignored). Disabling scope later makes all members of an entity fall due together. `srs.drill` (1..5, code `bad_drill`) is reserved: the web engine asks 1 item per slot. Per-unit settings overrides do not include `scope`.
  - Config shape: `srs:{ladder?, dropOnWrong?, scope?, drill?, mode?}`, `srsByType:{<type>:{ladder,...}}`, exam `{id (required in exams[]), minutes?, passMark?, pass?, sections:[{title,count,units?,tags?,types?}], timing?, scoring?, passPoints?}`. dojo-core resolves the pass mode (`pass.mode`, else `points` when `scoring` is set, else `percent`; `crates/dojo-core/src/exam/mod.rs:11`); a missing `passMark` means `DEFAULT_PASS_MARK` 0.6 (`crates/dojo-core/src/exam/sample.rs:8`).
- `content/<unit>.jsonl`: one item per line. Common fields: `id` (stable, append-only), `type`, `unit`, `tags[]`, `prompt`, `explanation?`, `source?` (reference into the course MAP, not copied text), `stimulus?` (id of a shared passage in `stimuli.jsonl`), `entity?` (id shared by items that belong together, e.g. a kanji and its words; default the item's own id), `topic?` (catalog label, see below), `meta?` (free-form, ignored by core), plus type fields:
  - `topic`: optional non-empty string, at most 80 characters. Catalog rows and the detail header show it; the display chain is `topic` > `meta.title` > intro title > listening answer > `detail.glyph` value > stimulus title > unit title > entity/id (`topicLabel`, `web/ui/detail.js`). The catalog never shows the prompt, and search indexes `topic` as well. Validator: `bad_topic` (error, empty or blank), `topic_too_long` (warning, over 80), `topic_is_prompt` (warning, equal to `prompt` after normalizing).
  - `choice`: `options[]`, `answer` (index or indices); `gap`: `answers[]`, `normalize`, `retry?`, `inputMode?` (`numeric` | `decimal` | `text`; sets the input's `inputmode` attribute, display only; any other value is a content parse error); `card`: `front`, `back`.
  - `multi`: `options[]` (>=3), `correct[]` (indices, fewer than options); `match`: `pairs[{left,right}]` (2..8), `distractors[]?`; `order`: `steps[]` in correct order (2..10); `cloze`: `parts[]` (string = literal text, array = blank with accepted alternatives; 1..10 blanks), `normalize?`; `numeric`: `answer`, `tolerance?` (absolute, default 0), `unitLabel?` (display only).
- Ids: `<prefix>-<n>` (`^[a-z][a-z0-9]*-[0-9]+$`), opaque and never reused or renumbered. `unit` is a plain field, so moving an item does not change its id. `ids.lock` (`{v:1, ids, retired, types}`; ids sorted, `types` maps id to item type) is written by `dojo lock` and `dojo build`. `dojo validate` fails on a removed id or a reused retired id; content edits are allowed. `status:"retired"` items may stay in shipped data (skipped by queues) or be removed from the content; a removed id stays in `ids.lock` `ids` and `retired` and is never reused. Changing an item's type or correct answer requires retiring it and adding a new id; `validate` warns `item_type_changed` when the type differs from the lock. Without a lock `dojo` treats the course as new.
- Plugins (build-time only): `course.json` `plugins.{scripts,styles}` hold paths inside the course folder (no absolute paths, no `..`). `dojo build` inlines them at the `@course` marker of `web/bundle.json`; they register hooks in `DojoExt` (`web/ext.js`): `markup`, `beforeSubmit` (may only block with a message, never rewrite the graded input), `detail` (called by the Catalog detail view and by the session feedback with deep copies of the item, `items` and `records`; the hook ctx has an `introRendered` boolean, true when the DojoExt.intro hook returned output for this item in the open detail view (false otherwise, including when the default intro body is shown), `feedback` (true when called from the session answer feedback, absent in the Catalog; also set for `intro` hooks there) and `correct` (session feedback only: true when the answer was right; the detail hook then renders alone, without declarative detail or tags, so it should return nothing for items it does not want shown on a correct answer); returns a vnode or nothing; a throwing hook renders nothing), `intro` (`registerIntro(fn(intro, item, ctx))`: body of the intro card, null = default title + text) `preAnswerText` (`registerPreAnswerText(fn(item, text) -> string)`: text of `item.explanation` in the inline intro before the answer; non-string result or throw keeps `text`, empty hides the intro), and `voiceRank` (`registerVoiceRank(fn(voice, role) -> number)`: higher ranks first among speech voices; 0 on error). Plugin settings are per-browser choices stored at `doc.settings["plugin:<key>"]`. Nothing is fetched or loaded at runtime; plugins never touch grading, scheduling or progress.
- New item type = variant in the core `Item` enum + a `check` arm + `web/types/<type>.js`. Self-graded types need no core logic. Cargo features only for heavy dependencies.
- `dojo build` writes `<out>/<course-id>/` (default `<out>` = `dist`) with `index.html` (app, WASM, i18n, vendored Preact inlined), `data/content.json` (`v`, `course`, `items`, `version` hash, `lock`, optional `stimuli`, optional `intros`) and `manifest.json` (files, sizes). Preact is never loaded from a CDN. Limits: warning above 8 MiB, failure above 16 MiB.

## 5. Progress model
Document: `{v:1, course, t, resetAt, items:{id:{s,due,ok,bad,last,...,e?,cf?,to?}}, stats:{days,newByDay,...}, settings:{...,ts:{}}, exams:{key:{...}}}` plus optional `examDraft` and `intros:{<entity>: firstSeenMs}`. Record extras `e, cf, to` and settings `timer:baseMs`, `timer:scale`, `timer:streak`.

- `course:<id>` is set on the document; merge and import reject a document for another course.
- sanitize is lossless: unknown fields are kept at every level, a foreign document becomes null. It never clamps `s` (stage); clamping happens only when scheduling. `deny_unknown_fields` applies to content only; progress types carry extra fields through (`serde_json` `float_roundtrip` + `preserve_order`).
- merge: union by id; later `last` wins, higher stage breaks ties; stats merge by max per date; the newer `resetAt` wins the whole document (older records and drafts are dropped). Exams are a union by key. `intros` is a union by entity with the smallest timestamp; entries older than `resetAt` are dropped; sanitize keeps only numeric values, and documents without `intros` stay without it.
- Stats merge is generic: any `stats.*` map whose keys are all dates merges per day by max (`days`, `newByDay`, `extraNewByDay`, and the per-unit maps `stats["newBy:<unit>"]`). Newest 150 dates are kept.
- Settings merge per field by `settings.ts[field]` (a timestamp). A `null` value with a newer `ts` is a tombstone and survives sanitize and merge. Settings keys: global ones (`newPerDay`, `theme`, `examDate`, `placementDone`, ...), per-unit overrides `unit:<unitId>:<field>` with fields `newPerDay` (0..50), `ladderScale` (0.25..4), `dropOnWrong` (0..10), `newOrder` (`file` | `random`), per-group overrides `group:<groupId>:<field>` with fields `newPerDay` (0..50), `newOrder` (`file` | `random`), `onlyTags` and `extraRandom` (booleans), plugin settings `plugin:<key>`, and clip flags `clipFlag:<clipId>` (`true` = the user marked the recording bad; un-flag writes the `null` tombstone). Clip flags are ordinary settings fields: per-field merge by `ts`, kept by Reset (Reset keeps settings), no `v` change, old clients carry them through untouched.
- Precedence of unit settings, highest first: per-field override `unit:<unitId>:<field>` > course-level config resolved by dojo-core `unitConfig` (unit `srs`/`newPerDay`/`newOrder` > `srsByType[type]` > course `srs`/`newOrder` > defaults). Default ladder `[0,4h,1d,3d,7d,14d,30d]`; default drop on wrong 1 stage. The global daily allowance is `settings.newPerDay` (default 10); unit caps apply on top.
- `examDraft` (optional, top level): one exam-resume slot `{sid, updatedAt, ...}`, open or closed (`closed` = `finished` | `abandoned` | `expired`, plus `closedSids[{sid, updatedAt}]`, newest 32). Merge is a join: the newest slot by `updatedAt` (ties by `sid`) wins and `closedSids` are unioned; a closed sid is never reopened.
- Frozen before any user has data: doc shape `v:1` and field names; localStorage key; db path `data/users/<uid>/progress-<courseId>`; id strings and `courseId`; `exams[].id` once published; timestamps are ms epoch; day keys are local `YYYY-MM-DD` with `today` passed in from JS; stage = index into the ladder (ladders may only grow at the end); exam key format. Schema changes are additive only; `v` never changes.

## 6. Storage adapters
JS, in `web/storage.js`. Interface: `load()`, `update(fn)` (load -> merge -> save), `attachLifecycle(win)`; export/import text for paste.
1. `artifact-db`: `window.claude.use('db')` + `use('user')`, document path `data/users/<uid>/progress-<courseId>`. Document paths alternate collection/document, so the course id is part of the document name. Falls back to `local` when the API is unavailable.
2. `local`: localStorage, key `dojo.<courseId>.progress.v1`; unreadable data is backed up to `<key>.unreadable.<ts>`.
3. `paste`: export = JSON in a textarea with a Copy button; import = paste + merge (downloads are inert in artifacts).
- Every save is load -> merge -> save (artifact-db has no compare-and-set); never overwrite stored data with an empty state. Writes are debounced; a final flush runs on `pagehide` and `visibilitychange`.
- Paste import merges and never sets `resetAt`; only the explicit Reset does (test `paste_import_never_sets_resetAt`).
- Storage failure must not break the app.

## 7. CLI behaviour
- `dojo schema (--out <dir> | --brief)`: writes `course.schema.json` and `item.schema.json`, or prints the compact cheat-sheet of item types for AI prompts.
- `dojo validate <course-dir> [--json] [--strict] [--web <dir>]`: schema (generated from Rust types), id lock, duplicates, answer leakage in prompt, length limits, unit refs, exam/section refs, prompt length (over 600 chars warns), plugin paths. Course UI translation files `i18n/<lang>.json` are checked against `web/i18n/en.json` (`i18n_missing_key`, `i18n_unknown_key`, `i18n_placeholder`, `i18n_not_string`, `i18n_bad_file`; symlinked files are rejected, as in `build`). Output: human text, or `--json` `{ok, errors, warnings, diagnostics:[{severity,code,file,line,message}]}` so any AI can self-correct. `--strict` makes warnings fail.
- `dojo lock <course-dir>`: rewrites `ids.lock`.
- `dojo build <course-dir> [--out <dir>] [--wasm <file>] [--web <dir>] [--strict]`: validate -> refuse on errors -> emit the files of section 4 -> rewrite `ids.lock` -> report sizes. Copies audio manifest to `data/audio/manifest.json` and packs to `data/audio/<file>`; new limits: any single file > 16 MiB fails, whole dist > 60 MiB fails, > 250 files fails; old 8/16 MiB content gates unchanged. `web/` is found by walking up from the current directory unless `--web` is given.
- `dojo init <course-id> [--title T] [--ui LANG] [--content-lang LANG] [--workspace DIR]`: scaffolds a minimal course (default `workspace/<course-id>/`).
- `dojo import-progress <old.json> --map <id-map.json> --course <dir> [--out <file>] [--write] [--now <ISO>]`: converts legacy progress to v:1; dry-run unless `--write`.
- `dojo stats <course-dir> [--json]`, `dojo next-id <course-dir> <prefix> [--count N]`, `dojo add <course-dir> <unit-id> [--file F] [--dry-run]` (appends items from JSON on stdin or a file, all-or-nothing, assigns ids above the highest existing).
- Exit codes: 0 ok, 1 validation or build refusal, 2 usage or I/O error.
- Validator codes: the list is `CODES` (`crates/dojo-core/src/validate/codes.rs`); its length is `CODES.len()` and is not fixed in this document. `dojo schema` prints them under "VALIDATOR CODES".

## 8. Testing
- Rust unit and integration tests in `crates/dojo-core` and `crates/dojo-cli` (the latter spawn the binary on fixtures and `examples/`).
- Golden vectors in `tests/vectors/*.json` (srs steps, merge cases incl. diverged docs, foreign doc and unknown fields, answer normalization, exam scoring, timer, extras, weighted), generated by `tests/gen-vectors.js` from the frozen reference JS in `tools/reference/`. Rust must match them byte-for-byte after stable-sorted JSON. `node tests/gen-vectors.js && git diff --exit-code` must be a no-op.
- `node tests/wasm-smoke.js` runs the vectors through the compiled WASM and enforces the 512 KiB budget.
- Web: `node --test web/tests/*.test.js` (with a mock `window.claude`, see `web/dev/mockdb.js`).
- Commands are listed in `docs/ARCHITECTURE.md`.

## 9. Build/toolchain
Rust edition 2024, target `wasm32-unknown-unknown`, release profile `opt-level="z"`, `lto`, `panic="abort"`; `scripts/build-wasm.sh` builds the WASM. A prebuilt `.wasm` release is planned, not available; building needs the Rust toolchain.

## 10. Hard rules
- sanitize never clamps stage; clamp only when scheduling (read time).
- Progress types are lossless: unknown fields survive at every level; a test vector has unknown fields at every level.
- Stats merge is generic over date-keyed maps (no fixed key list).
- Every save is load -> merge -> save; final flush on `pagehide`/`visibilitychange`.
- Paste import merges and never sets `resetAt`.
- The exam sampler is deterministic: it takes `seed` and `now`, uses a fixed PRNG (splitmix64) and is checked against vectors.
- Watch `r.s|0` truncation, Number vs i64 and key order when the JS oracle and Rust are compared.

## 11. Layers and deploy targets
Three separate things that never mix:
1. **Framework** = this repo (MIT, public). No course content, no progress, no keys.
2. **Workspace** = the user's own data: `materials/` (sources) and the generated course (`course.json`, `content/*.jsonl`, `ids.lock`, `dist/`). Default location `workspace/<course>/` inside the repo folder (git-ignored); `--workspace <path>` puts it anywhere. Nothing needs to be committed.
3. **Progress** = stored only where the published app lives, via the storage adapter of the deploy target. Never written into the repo or workspace (except an explicit paste-export the user copies).

Typical flow, as in `AGENTS.md`: ingest materials -> generate content -> `dojo validate` -> `dojo build` -> publish step of the target (the `make-trainer` skill). Publishing to the same artifact URL keeps progress; a new artifact is a new db with empty progress, and paste-export is the backup.

The `artifact` target is the only one implemented: default storage artifact-db with local fallback and paste export; no code runner (CSP). Core, content format and UI do not depend on the target; only the build emitter, storage adapter and publish steps would. `ids.lock` is generated state kept in the workspace and also embedded in the published `data/content.json` (`lock`).

## 12. Audio, timers, weighted scheduling

### 12.1 Audio assets
- course.json `audio?: {manifest: "<path in course dir>", base?: "<URL or relative prefix>"}`. `manifest` is relative to the course dir with `/` separators; absolute, or containing a `..` component -> `audio_path_escape`; empty -> `audio_without_manifest`. The course-side `audio` and `timer` objects reject unknown fields like the rest of course.json.
- Manifest `{v:1, packs:[{file, bytes, sha256?, enc?:"raw"|"base64" (default "raw")}], clips:{<clipId>:{pack, off, len, ms, mime, credit?, text?, tr?: {<lang>: string}, mt?, supersedes?: [clipId]}}}`. `supersedes` is optional and additive (the validator ignores it like any unknown field); the web loader's `clipMeta(id)` returns it as an array of strings, `[]` if absent.
  Unknown fields at any manifest level are ignored (additive v1 extensions). Invalid JSON, a wrong type or a missing required field -> `audio_bad_manifest` whose message contains the parser error text.
  `file` is a bare file name `^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$`, resolved against the directory that contains the manifest (not the course dir). Example: manifest `audio/manifest.json`, pack on disk `audio/pack-00.mp3`, `file: "pack-00.mp3"`; the dist `manifest.json` lists packs under the same name. The hosting artifact serves no `.bin` extension: a pack is a concatenation of complete MP3 files published as an ordinary served file named `*.mp3` with contentType `audio/mpeg`; the loader reads it as raw bytes (`enc: raw`). Packs are never required to play as a single MP3.
  `audio_bad_manifest` also for: `v != 1`; empty `packs`; `file` not matching the pattern; clipId not matching `^[a-z0-9][a-z0-9-]{0,63}$`; `pack >= packs.length`; `len == 0`; byte range outside the decoded pack: raw `off + len > bytes` (checked add), base64 `off + len > floor(bytes/4)*3`; clip `text` or a `tr` value empty after trim, over 400 characters (Unicode scalar values) or containing a control character (U+0000-U+001F, U+007F); `tr` without `text`, with 0 or more than 8 entries, or a key not matching `^[a-z]{2,3}(-[A-Za-z0-9]{2,8})?$`; `mt: true` without `tr`.
- stimuli.jsonl gains `audio?: [clipId]`: 1..32 distinct ids (variants of the same utterance), else `audio_bad_stimulus`. `hideText` + `audio` = listening stimulus.
  A stimulus with `audio` while course.json has no `audio` -> `audio_without_manifest` at `stimuli.jsonl:<line>`. Each listed id missing from the manifest -> `audio_unknown_clip` at `stimuli.jsonl:<line>`, once per id per stimulus; skipped when the manifest could not be loaded or parsed (one error, no cascade).
- Validator codes (errors): `audio_without_manifest`, `audio_path_escape`, `audio_manifest_missing`, `audio_bad_manifest`, `audio_bad_stimulus`, `audio_unknown_clip`, `audio_pack_missing` (no file `<manifest dir>/<file>`), `audio_pack_mismatch` (file size != `bytes`). `sha256` is informative: dojo-kit has no hash crate and adds none; course tools check it.
- Diagnostic order is deterministic (stable CLI JSON): course.json audio checks; manifest read/parse; manifest structure (`v`, empty packs, packs by index, then clips in ascending clipId byte order: id, pack index, len, range); pack files by index (missing, size); stimuli.jsonl in line order (list size/duplicates, without manifest, unknown ids in list order). No HashMap/HashSet iteration order reaches the output.
- `dojo build` copies the manifest to `data/audio/manifest.json` and each pack from `<manifest dir>/<file>` to `data/audio/<file>` (not inlined), lists them in manifest.json.
  `dojo build` fails above 16 MiB per file, 60 MiB per dist, 250 files; the artifact host limits are 16 MB / 64 MB / 255 files (decimal MB), so keep each pack under 15 MB. Old 8/16 MiB content gates unchanged.
- Provenance (per-clip source record) stays in the course (`audio/sources.jsonl`); only optional `credit` ships. The framework repo ships no audio; tests use synthetic bytes/tones.
- Web `web/audio.js` (`DojoAudio`): base = `window.DOJO_AUDIO_BASE` > `course.audio.base` > `data/audio/`; a pack URL is base + `file` (swap for Cloudflare R2 later, no core change).
  Lazy pack fetch + per-pack cache; decode via `AudioContext.decodeAudioData` (no media-src needed); iPhone Safari can fail `decodeAudioData` on a sliced MP3; the player then falls back automatically to an `Audio` element with a Blob URL (owner phone test G0: raw binary packs work). `play(clipId) -> Promise<{ms}>` resolves at playback end.
  iOS: `unlock()` runs inside the tap (creates/resumes the context, plays a silent buffer, primes the Audio element reused by the fallback) and starts `preload()` (manifest + all packs). Safari/iOS (UA or `webkitAudioContext` only): the Audio element with a Blob URL is the primary path and `decodeAudioData` is not called; when manifest and pack are preloaded `play()` reaches `Audio.play()` synchronously inside the tap. Elsewhere: `decodeAudioData` (callback form, 3 s timeout) -> Audio element with a Blob URL -> Audio element with a `data:` URL (blob: blocked). Duration: manifest `ms`, or when 0/missing the measured buffer/`Audio.duration`; `play(id, {onStart({ms})})`, `duration(id)`. While a clip plays the play control shows a `play-track` progressbar (`aria-valuenow` elapsed s, `aria-valuemax` total s). One active playback: `play()` of the clip already active returns the same promise; any other `play()`/`stop()` first stops and releases the previous clip (pause, currentTime 0, Blob URL revoked); a request superseded while loading never starts; the unlock priming element is paused after its silent play. Debug line `audio-debug` (manifest/pack status, ctx.state, decode error name, play() rejection name, path webaudio|blob|data, last step, err) only with settings `debug` or URL `#debug`.
  Variant pick: `ctx.random` among `stimulus.audio`, never the variant played last for that stimulus in this session (a single variant is replayed). Failure -> `speak` via DojoSpeech if present, else show text + notice; never blocks grading.
- Clip flags (bad recording): on the feedback screen of a non-exam answer whose clip was heard (`DojoAudio.heardClip`), a button sets `settings["clipFlag:<clipId>"] = true` (pressed again: `null` tombstone). The engine's `stimulusOf` returns the stimulus with flagged ids removed from `audio` (content and records untouched); with no clip left it falls back exactly like a failed clip: `speak` via DojoSpeech, else a notice is shown and the text stays hidden until the answer. Settings list the flagged clips (un-flag, copy `{"ids":[...]}`); the course turns that list or a progress export into `audio/blocklist.json` and rebuilds. Flags never delete or lower progress.

### 12.2 Per-question timer (adaptive)
- course/unit `timer?: {baseMs?: integer 2000..30000 (default 8000), adaptive?: bool (default true), replays?: integer 0..3 (default 1)}`; out of range -> `bad_timer`; negative or non-integer -> course.json parse error. Not in exams (exam timers unchanged).
  Defaults are materialised: `data/content.json` always carries all three fields of a present `timer`; the web reads them; a missing or non-finite `timer.baseMs` falls back to 8000 in `web/session/qtimer.js` (defensive). Effective timer = the unit `timer` if present, else the course `timer`, as a whole object (no per-field merge).
- User setting `timer:baseMs` (settings, per-field ts): when a finite number, clamped to 2000..30000, it replaces the effective `baseMs`. Adaptive state `timer:scale` (0.5..2.0, default 1) and `timer:streak` in settings (existing per-field merge; no merge change).
- Input normalisation, identical in the JS reference and Rust (stored settings may be tampered): `scale` finite number -> clamp to [0.5, 2.0], else 1. `streak` finite number >= 0 -> floor, else 0. `baseMs` finite number, else 8000. Only `outcome === "correct"` is correct; any other value ("wrong", "timeout", unknown) is handled as wrong. fast = `answerMs` and `limitMs` are finite numbers and `answerMs <= 0.8*limitMs`.
- Core `timerNext({scale, streak, outcome, answerMs, limitMs}) -> {scale, streak}`, after normalisation:
  not correct: scale = round4(min(2.0, scale*1.2)), streak = 0.
  correct and fast: n = streak+1; if n >= 3: scale = round4(max(0.5, scale*0.9)), streak = 0; else scale = round4(scale), streak = n.
  correct, not fast: scale = round4(scale), streak = 0.
- Core `timerLimit({baseMs, scale}) -> ms` = clamp(round(baseMs*scale), 1500, 60000), after normalisation. Example: 8000 -> wrong -> 9600 -> 3 fast correct -> 8640.
- Float rules: operations in exactly the order written. round4(x) = round(x*1e4)/1e4; round = half away from zero (Rust `f64::round`, JS `Math.round`; equal because every rounded value here is >= 0); never `floor(x+0.5)`.
- Clock starts when the clip ENDS (render time if no audio); a replay restarts the playback track only and neither restarts, extends nor stops the clock; if the clip fails to play (any error) the clock starts at once so the question cannot hang. Expiry submits the CURRENT field contents: if they equal the correct answer the answer counts as correct (not timed out); otherwise (empty or wrong) it is wrong with `timedOut:true`. Feedback after expiry shows the correct answer in French words AND digits (e.g. "three hundred - 300").

### 12.3 Record extras and confusions
- Core `applyExtras({rec, correct, given, timedOut, weighted}) -> rec`. A flag is set only when it is exactly `true`. `rec` that is not a plain object (absent, null, array) -> `{}`. Never touches s/due/ok/bad/last or unknown fields. Only `e`, `cf`, `to` are written, each only when its rule fires; a field whose rule does not fire is copied unchanged, even if malformed.
- `e` (error EWMA; only when `weighted`): e0 = `e` when a finite number, clamped to [0, 1], else 0.5; e' = round4((0.7*e0) + (0.3*x)), x = 0 if correct else 1. Example 0.5 -wrong-> 0.65 -correct-> 0.455.
- `to` (only when `timedOut`): to' = min(2^53-1, t + 1), t = floor(`to`) when a finite number >= 0, else 0. Written as a JSON integer.
- `cf` = confusions as an ordered list of pairs `[[given, count], ...]`, at most 8, oldest first. Counted when not correct, not timed out, `given` is a string and key = trim(given) has 1..16 Unicode scalar values.
  trim strips leading and trailing characters of the Unicode White_Space set: U+0009..U+000D, U+0020, U+0085, U+00A0, U+1680, U+2000..U+200A, U+2028, U+2029, U+202F, U+205F, U+3000 (= Rust `str::trim`; JS `String.prototype.trim` differs on U+0085 and U+FEFF and is not used). Length = code points (JS `[...s].length`, Rust `s.chars().count()`).
  Steps: (1) normalise the stored value: not an array -> `[]`; keep entries that are 2-element arrays `[string of 1..16 scalar values, count]` with count an integer in 1..2^53-1; drop other entries and any later duplicate of a key (first wins). (2) key present -> count = min(2^53-1, count+1), position unchanged; else append `[key, 1]`. (3) while more than 8 entries: remove the entry with the lowest count among the entries other than key; ties -> the earliest (lowest index). The new key always enters.
  Counts are written as JSON integers. Display order (stats UI): count desc, ties lower index first.
- Vectors: `e`, `scale` and weights compare as numbers (a port may write `1.0` where JS writes `1`); counts compare as exact integers; `cf` order is exact.
- Web calls it after applyAnswer only when the unit has `timer`, `srs.mode:"errorWeighted"` or course `confusions:true`. Courses without these fields write exactly what they write today.
- Progress: extras live inside item records; sanitize already keeps unknown record fields (deep clone, arrays included), merge takes the whole record by `last`, so old builds keep them (checked on master e595c61 with a sanitize/merge roundtrip). Known limit: concurrent devices lose one side's increments (same as ok/bad today). `cf` never shipped as an object, so there is no migration; an object-shaped `cf` from a pre-release dev build is normalised to `[]` at the next counted confusion.

### 12.4 errorWeighted scheduler mode
- `srs.mode?: "ladder"|"errorWeighted"` in course `srs` and `units[].srs` (an enum: any other value is a course.json parse error naming the allowed values); not in `srsByType` (`mode_by_type`). Absent = ladder. Ladder records still written (s/due), so switching modes loses nothing.
- Core `weightedQueue({ids, records, now, seed, limit, newAllowance}) -> [id]` (deterministic, splitmix64 as in exam `sample`):
  Inputs: `ids` duplicates dropped (first kept). `limit`, `newAllowance`: finite number -> max(0, floor(x)), else 0. `seed`: decimal string of an integer 0..2^64-1; anything else is a caller error (JS throws, Rust returns Err). `now`: ms. An id has a record iff `records` has an OWN property `id` whose value is a non-null, non-array object; anything else is new.
  Record fields: e0 = `e` when a finite number, clamped to [0, 1], else 0.5; b = min(5, floor(s)) when `s` is a finite number > 0, else 0; staleDays = clamp(floor((now - last)/86400000), 0, 7) when `last` is a finite number, else 7. A new item has e0 0.5, b 0, staleDays 7.
  candidates = ids with a record + the first `newAllowance` ids without one (input order).
  weight = ((0.15 + e0) * BOXF[b]) * (1 + ((0.5 * staleDays) / 7)), in exactly this operation order (vectors compare unrounded f64). BOXF = [1, 0.7071067811865476, 0.5, 0.35355339059327373, 0.25, 0.17677669529663687] (a table, not pow: JS and Rust pow may differ by 1 ulp). Examples: new item 0.975; e .455, b 1, stale 0 -> 0.4278 (4 d.p.).
  Worst-first: candidates with a record whose `e` is a finite number (an absent `e` does not qualify, so a ladder -> errorWeighted switch promotes nothing), e0 >= 0.3, by e0 desc (ties input order), at most 5, then at most `limit` of them.
  Sampling fills the remaining `limit - head` slots from pool = candidates minus head, input order. Per draw: v = next splitmix64 output (state starts at seed); r = (v >> 11) / 2^53 (exact, 0 <= r < 1); total = left-to-right sum of the current pool weights starting at 0.0, recomputed every draw (no running subtraction); target = r * total; pick the first index whose left-to-right running sum (from 0.0) is > target, or the last index if none is; remove it; repeat until the slots are filled or the pool is empty.
  Output: unique ids, length min(limit, candidates). Vector group `unitRandom` ({seed, n} -> first n values of r) pins the conversion.
- Web: daily/practice sessions of errorWeighted units use it; wrong answers reuse the existing relearn requeue. Weak list uses e in this mode.
